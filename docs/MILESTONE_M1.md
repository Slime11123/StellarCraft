# StellarCraft — 里程碑 M1:双角色切换 + 史蒂夫核心能力

> 目标:在《剑星》里**自由切换 Eve 与史蒂夫**。切到史蒂夫时,拥有 Minecraft 的能力——建造方块、打开背包、点燃 TNT 爆炸并对 Naytiba 造成真实伤害。
>
> 这是 StellarCraft 的第一个**可玩、可验证**的里程碑。它有意绕开了最难的部分(剑星地形碰撞、完整世界导出),聚焦于"能玩起来"的最小闭环。

## 2. 核心状态机:双角色控制

这是本里程碑**最核心、也最容易做错**的部分。

### 2.1 状态定义

```
                     ┌────────────── 控制权在 EVE ──────────────┐
                     │  Eve 正常游玩,MC 客户端冻结               │
                     │  史蒂夫(MC玩家)在剑星世界中的锚点待机     │
                     └──────────────────┬───────────────────────┘
                                        │  按 F4
                                        ▼
                     ┌────────────── 控制权在 STEVE ─────────────┐
                     │  史蒂夫接管输入,MC 物理/背包/方块全开      │
                     │  Eve 进入待机(AI 跟随或原地),隐藏 HUD      │
                     └──────────────────┬───────────────────────┘
                                        │  按 F4
                                        └──────────► 回到 Eve
```

### 2.2 各状态下的职责

| 维度 | 控制权在 Eve | 控制权在 Steve |
|---|---|---|
| **输入路由** | 剑星自己的输入系统 | MC 输入处理器(经 InputBridge 转发) |
| **Eve 行为** | 正常可玩 | 待机:原地 / 跟随史蒂夫(可配置) |
| **史蒂夫行为** | 冻结在锚点(不可见或静止) | 完整 MC 玩家:物理/背包/方块/战斗 |
| **相机** | 剑星相机 | MC 相机(第一/第三人称) |
| **HUD** | 剑星 HUD | MC HUD(快捷栏/红心/准星) |
| **MC 模拟** | 冻结(菜单状态) | 运行 |

### 2.3 切换流程(伪代码)

```
on_hotkey(F4):
  if control == EVE:
    # 切到史蒂夫
    sb.freeze_eve_input()           # Eve 输入失效
    sb.set_eve_ai_wait_or_follow()  # Eve 待机
    sb.hide_sb_hud()
    mc.unfreeze()                   # MC 客户端解冻
    mc.set_player_at(sb.player_pos) # 史蒂夫出现在 Eve 当前位置
    mc.grab_input()                 # 输入转给 MC
    control = STEVE
  else:
    # 切回 Eve
    mc.freeze()
    mc.drop_input()
    sb.unfreeze_eve_input()
    sb.show_sb_hud()
    control = EVE
```

## 3. TNT 爆炸 → Naytiba 伤害(卡点 2 的完整链路)

这是本里程碑里**唯一全新的跨游戏机制**,值得单列。

### 3.1 链路

```
[MC] 玩家点燃 TNT
  → MC 原生引爆(有半径、有伤害随距离衰减)
  → ExplosionMixin 捕获爆炸事件
  → 枚举爆炸半径内的 ActorProxy(隐形实体)
  → 对每个代理计算距离衰减后的伤害
  → 写 kEvExplosion {center, radius, perActor: {uid, damage}}
  → 剑星 DamageApplier 读取事件
  → 对每个 uid 对应的真实 Naytiba:
       - 用剑星受击系统施加伤害(掉血/硬直/仇恨/音效)
       - 施加爆炸击退(Impulse)
  → Naytiba 死亡走剑星原生死亡流程
```

### 3.2 伤害换算

- MC TNT 爆炸对实体伤害:约 7~56 点,随距离衰减。
- 剑星 Naytiba 血量:普通杂兵约 100~300,精英/Boss 上千。
- **因此要缩放**:`剑星伤害 = MC伤害 × kTntScale`(`kTntScale` 初值建议 10,可配置)。
- 爆炸**半径**直接复用 MC 的 TNT 爆炸半径(约 4 方块),换算成剑星单位(×100 UU)。

### 3.3 关键实现点

- **MC 侧**:需要 Mixin 到 `PrimedTnt` / `TntBlock` 的引爆逻辑,捕获爆炸中心+半径+受影响实体列表。原版 MC 爆炸已经算好了"哪些实体在范围内、各受多少伤害",直接复用这部分计算,不重写。
- **剑星侧**:需要一个 `DamageApplier` 模块,把 uid 映射回真实 Actor,调用剑星的伤害函数。UE4SS 的 live property editor 可用于先探测"哪个函数是伤害入口"。

## 4. 方块渲染(卡点 3 的 MVP 方案)

- MC 离屏渲染方块层(透明背景)→ 读回像素 → 写共享内存 overlay 槽 → 剑星合成。
- **MVP 用 CPU 读回**(`glReadPixels` / PBO),约 1 帧延迟,可接受。
- 方块与剑星几何的**遮挡**:MVP 阶段先不做深度测试(方块总是画在剑星之上),这是已知的视觉瑕疵,后续用共享深度缓冲解决。

## 5. 为 M1 新增/修改的协议消息

现有协议已覆盖大部分,需补充/明确以下事件:

| 消息 | 方向 | 用途 |
|---|---|---|
| `kEvExplosion`(已有) | MC→SB | 爆炸中心+半径 |
| **新增 `kEvExplosionHit`** | MC→SB | 每次爆炸对每个 uid 的伤害,批量 |
| `kInHurt`(已有) | SB→MC | Naytiba 反打史蒂夫 |
| **新增 `kInSwitchControl`** | SB→MC | 通知 MC 切换控制权(或 MC 侧检测 McState.flags) |
| **新增 `kEvSwitchAck`** | MC→SB | MC 确认切换完成 |

> 说明:切换控制权主要靠 `SbState.flags` 加一个 `kSbControlSteve` 位 + MC 侧 `kMcControlSteve` 位来表达,显式事件用于同步时序。

## 6. 为 M1 新增/修改的代码模块

### MC 侧(Java)
- **`ControlStateMachine`**(新):持有当前控制权,处理 F4 热键,驱动 freeze/unfreeze。
- **`ExplosionMixin`**(新):Mixin `PrimedTnt`/爆炸逻辑,捕获爆炸并转发。
- **`InputBridge` 路由**:根据控制权决定输入给谁(已有骨架,补状态判断)。

### 剑星侧(C++)
- **`control_switch.cpp`**(新):F4 热键监听 + Eve 待机控制 + 相机切换。
- **`damage_applier.cpp`**(新):读 kEvExplosion 事件,对 Naytiba 施加伤害+击退。
- **`actor_mirror.cpp`**:已有,确保 Naytiba 的 uid 稳定可映射回真实 Actor。
