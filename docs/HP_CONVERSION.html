1　换算是怎么算的

只狼方案的原始实现（native_combat.hpp:29 与 :157）只有三行，核心是不看原生血量，只看档位：

// 档位预算：普通敌人 40 点 MC 伤害，Boss 200 点
int healthPoints(const Vital &v) const { return v.bossNode > 0 ? bossHealthPoints_ : normalHealthPoints_; }

// 把「MC 伤害」换成「扣掉百分之几的血条」，再乘回去
auto target = damageHp(v.hp, v.maxHp, cmd.amount / healthPoints(v), 0);
结论：只狼定义的不是汇率，是预算。40 点 MC 伤害 = 打空一条普通敌人血条，200 点 = 打空一个 Boss 阶段血条；原生血量是多少完全不参与运算。

本文档把同一套模型套到剑星上：按剑星自己的 5 个敌人档位各给一个击杀预算，再用真实血量反推出等效汇率 k = 原生HP ÷ 预算，供 Stellar Blade 侧扣血时使用。

护盾怎么处理：剑星的护盾（Shield）是独立于血量的第二条槽，地位相当于只狼的姿态——只狼那边也是单独给姿态配一个比例。这里采用最简单的做法：护盾沿用同一个 k，MC 伤害先扣护盾、破盾后再扣血。不另设系数，避免再引入一组需要调参的数字。

4　为什么不能沿用「单一汇率」

如果把只狼的 40/200 理解成一个固定汇率，锚定「战士档 = 40 点」，得到全局 k ≈ 212.5，那么：

所以必须分档。剑星血量跨度约 950 倍（Creeper 384 → Elder Naytiba 366,000），只狼的血量跨度要小得多，所以它两档就够用。这也是本次换算唯一偏离只狼的地方——档位从 2 个扩到 5 个，但每个档位的预算定义方式与只狼完全一致：普通档 40、Boss 档 200 两个数字被原样保留。

5　落地到 StellarCraft

改动很小，因为现有链路已经够用——只需要把「固定倍率」换成「按档位查表」。

位置现在改成
sb-mod/lua/main.lua按类名前缀 CH_M_NA 判断是不是敌人再取 actor.MaxHP 判档，或维护一张 内部名 → 档位 表
damage_actor()直接从 Health 减绝对值改成 Health -= MaxHP × (MC伤害 ÷ 预算)
DamageBridge.MC_TO_SB_SCALE = 5.0f固定 ×5删除；协议改成传原始 MC 伤害，档位换算放到 SB 侧做
ExplosionMixin.SCALE = 10.0f爆炸固定 ×10保留，但改为「按档位归一化后再乘爆炸权重」
档位判定建议放在 Stellar Blade 侧，因为那边能直接读 MaxHP 和内部类名，判档准确率最高；MC 侧只管把「我打了多少点 MC 伤害」原样发过去即可。这样以后调平衡只改 main.lua 里的一张表，不用重编 jar。
